# Two Sum ([LeetCode 1](https://leetcode.com))

## Problem Statement

Given an array of integers `nums` and an integer `target`, return *indices of the two numbers such that they add up to `target`*.

You may assume that each input would have ***exactly* one solution**, and you may not use the *same* element twice.

You can return the answer in **any order**.

# Intuition

A nested loop brute-force search would compare every pair of numbers to see if they match the sum, costing an inefficient O(N²) quadratic runtime penalty. 

To optimize this down to a **single linear pass**, we can use a **Hash Map Lookahead** strategy:
- As we traverse the array from left to right, we don't just look for pairs blindly. Instead, at the current element `nums[i]`, we calculate its exact mathematical complement needed to hit the goal:
  \[\text{complement} = \text{target} - \text{nums}[i]\]
- We check our `HashMap` index directory to see if this `complement` value has already been logged.
  - If it **is present**, we have successfully closed the loop! We return the cached index of the complement along with our current index `i`.
  - If it **is missing**, we record the current number's value as a key mapped to its index position (`nums[i] -> i`) in the map directory so that downstream elements can find it.

---

# State Definition

The linear single-pass lookup table records structural complement pairs inside a map register:

```java
Map<Integer, Integer> map = new HashMap<>(); // Maps value payloads to their 0-indexed positions
```

---

# Recurrence / Structural State Condition

```text
For i from 0 to nums.length - 1:
    int complement = target - nums[i]
    If map.containsKey(complement) -> Return [map.get(complement), i]
    map.put(nums[i], i)
```

---

# Optimal Single-Pass Hash Map Solution

## Idea

We configure a single traversal loop. By computing complements and running O(1) constant-time hash directory queries on-the-fly, we eliminate the need for sorting or nested loop backtracking blocks.

---

## Java Code

```java
import java.util.HashMap;
import java.util.Map;

class Solution {
    public int[] twoSum(int[] nums, int target) {
        // Guard Condition: Degenerate arrays cannot form coordinate pairs
        if (nums == null || nums.length < 2) {
            return new int[]{};
        }

        // Hash map mapping element values to their corresponding index positions
        Map<Integer, Integer> map = new HashMap<>();

        // Core Step: Single linear scan pass lookahead check
        for (int i = 0; i < nums.length; i++) {
            int complement = target - nums[i];

            // If the complement target has already been processed and cached, we are done
            if (map.containsKey(complement)) {
                return new int[]{map.get(complement), i}; // Return pair indices instantly
            }

            // Cache the current element's value and index for future lookahead matches
            map.put(nums[i], i);
        }

        // Fallback boundary marker if no solution matches constraints
        return new int[]{};
    }
}
```

---

## Complexity Analysis

Let N be the total length of the input array `nums`.

### Time Complexity

```text
Time Complexity: O(N)
```
*Explanation:* The pointer loops through the N array elements exactly once. Inside the loop, hash map operations (`containsKey`, `get`, `put`) execute in O(1) average constant time, keeping the overall execution runtime strictly linear relative to the array size.

---

### Space Complexity

```text
Space Complexity: O(N)
```
*Explanation:* In the worst-case scenario where the matching pair resides at the absolute tail of the array, the `HashMap` will cache up to N - 1 entries on the heap, yielding a linear auxiliary space footprint.

# Key Takeaways

✅ Core fundamental paradigm for processing lookahead targets, tracking complementary states, and using hash directories to drop quadratic search traps.

✅ **The Single-Pass Optimization:** You do not need to populate the `HashMap` with all the array elements up front before running your checks. By checking for the complement *first* and then putting the active item into the map *second*, you prevent a number from matching with itself (which violates the constraint to not use the same element twice).

✅ Directly drives real-world microarchitectures like **high-speed asset matching engines** (e.g., matching buy and sell orders matching a target currency transaction cap in real-time), database unique key composite validators, networking router packet associations, and memory cache managers.
