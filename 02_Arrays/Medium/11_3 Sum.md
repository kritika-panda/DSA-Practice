# 3Sum ([LeetCode 15](https://leetcode.com))

## Problem Statement

Given an integer array `nums`, return all the triplets `[nums[i], nums[j], nums[k]]` such that `i != j`, `i != k`, and `j != k`, and `nums[i] + nums[j] + nums[k] == 0`.

Notice that the solution set **must not contain duplicate triplets**. You can return the answer in **any order**.

---

## Examples

### Example 1

```text
Input: nums = [-1,0,1,2,-1,-4]
Output: [[-1,-1,2],[-1,0,1]]
```

### Explanation

```text
The unique triplets that sum up to 0 are:
- nums[0] + nums[1] + nums[2] = (-1) + 0 + 1 = 0.
- nums[0] + nums[3] + nums[4] = (-1) + 2 + (-1) = 0.
- nums[1] + nums[2] + nums[4] = 0 + 1 + (-1) = 0.
Notice that the output contains only unique triplets.
```

---

### Example 2

```text
Input: nums = [0,1,1]
Output: []
```

### Explanation

```text
The only possible triplet does not sum up to 0.
```

---

### Example 3

```text
Input: nums = [0,0,0]
Output: [[0,0,0]]
```

# Intuition

A native brute-force approach using three nested loops would check all coordinate combinations, which triggers a highly sub-optimal $O(N^3)$ cubic runtime penalty.

To optimize the search down to an efficient **quadratic $O(N^2)$ time footprint with $O(1)$ auxiliary space**, we can combine **Sorting** with the **Two-Pointer (Meet-in-the-Middle) Pattern**:
1. **Sort the array upfront.** Sorting places identical items adjacent to each other, making duplicate filtering trivial. It also sets up structural order so we can manipulate sums predictably.
2. **Fix the Pivot Element:** We run a loop fixing a tracking cursor `i` from left to right. This fixed element `nums[i]` reduces our 3Sum problem down to a standard **Two Sum II (Sorted Array)** challenge for the remaining elements, searching for a target pair sum equal to `-nums[i]`.
3. **Bilateral Boundary Squeezing:** For each fixed `nums[i]`, we anchor two pointers: `left = i + 1` and `right = N - 1`.
   - Calculate `sum = nums[i] + nums[left] + nums[right]`.
   - If `sum == 0`, a valid triplet is found! We record it and slide both pointers inward (`left++`, `right--`).
   - If `sum < 0`, our value is too small. We move `left++` to find a larger element.
   - If `sum > 0`, our value is too large. We move `right--` to find a smaller element.
4. **Duplicate Pruning Guards:** To completely protect our results against generating duplicate triplets without paying a performance penalty for a post-processing `HashSet`:
   - If the active pivot `nums[i]` matches its predecessor (`nums[i] == nums[i - 1]`), we skip it.
   - Once a valid triplet is located, we advance `left` past any identical values (`nums[left] == nums[left - 1]`) and push `right` back past any identical values (`nums[right] == nums[right + 1]`).

# State Definition

The sorting-based dual-pointer reduction pipeline tracks spatial boundaries using three reference registers:

```java
int i = 0;              // Pivot pointer tracking the first element of our triplet
int left = i + 1;       // Squeezing pointer anchored at the lower bounds of the search space
int right = n - 1;      // Squeezing pointer anchored at the higher bounds of the search space
```

# Recurrence / Structural Squeezing Condition

```text
Sort(nums)
For i from 0 to n - 3:
    If i > 0 AND nums[i] == nums[i - 1] -> Continue (Skip duplicate pivots)
    
    left = i + 1, right = n - 1
    While left < right:
        sum = nums[i] + nums[left] + nums[right]
        if sum == 0:
            Record triplet
            left++, right--
            while left < right AND nums[left] == nums[left - 1] -> left++
            while left < right AND nums[right] == nums[right + 1] -> right--
        else if sum < 0:
            left++
        else:
            right--
```

# Optimal Two-Pointer Sorting Reduction Solution

## Idea

We sort the array upfront to group duplicates and enable direction-based search constraints. By combining a single pivot-tracking outer loop with an inner meet-in-the-middle squeezing pass, we extract strictly unique triplets completely in-place.

---

## Java Code

```java
import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;

class Solution {
    public List<List<Integer>> threeSum(int[] nums) {
        List<List<Integer>> result = new ArrayList<>();
        
        // Guard Condition: Arrays with less than three elements cannot form a triplet
        if (nums == null || nums.length < 3) {
            return result;
        }

        int n = nums.length;

        // Step 1: Sort the array upfront to group duplicates and structure monotonicity
        Arrays.sort(nums);

        // Step 2: Fix the pivot element 'i' sequentially
        for (int i = 0; i < n - 2; i++) {
            // Optimization Short-Circuit: Since the array is sorted, if nums[i] is greater than 0,
            // all subsequent elements will be positive as well, making a 0-sum mathematically impossible.
            if (nums[i] > 0) {
                break;
            }

            // Duplicate Guard A: Skip identical pivot elements to isolate strictly unique triplet roots
            if (i > 0 && nums[i] == nums[i - 1]) {
                continue;
            }

            // Step 3: Initialize the Meet-in-the-Middle Two-Pointer pointers
            int left = i + 1;
            int right = n - 1;

            while (left < right) {
                int currentSum = nums[i] + nums[left] + nums[right];

                if (currentSum == 0) {
                    // Valid triplet located -> compile structural match values
                    result.add(Arrays.asList(nums[i], nums[left], nums[right]));

                    // Advance both pointers inward simultaneously
                    left++;
                    right--;

                    // Duplicate Guard B: Skip identical elements for the left pointer boundary
                    while (left < right && nums[left] == nums[left - 1]) {
                        left++;
                    }

                    // Duplicate Guard C: Skip identical elements for the right pointer boundary
                    while (left < right && nums[right] == nums[right + 1]) {
                        right--;
                    }
                } else if (currentSum < 0) {
                    // Sum is too small -> shift the left bound forward to find a larger value
                    left++;
                } else {
                    // Sum is too large -> shift the right bound backward to find a smaller value
                    right--;
                }
            }
        }

        return result;
    }
}
```

## Complexity Analysis

Let N be the total length of the input array `nums`.

### Time Complexity

```text
Time Complexity: O(N²)
```
*Explanation:* Sorting the array takes $O(N \log N)$ time. The main outer loop runs $N$ times, and for each iteration, the inner `while` loop checks the remaining space linearly via the left and right pointers in $O(N)$ time. This nested $O(N \times N)$ execution bounds the total runtime quadratically to $O(N^2)$, which easily outpaces sorting-less hash lookups for triplet matching.

---

### Space Complexity

```text
Space Complexity: O(1) auxiliary space
```
*Explanation:* Highly optimal. Excluding the memory allocations required to store and return the final results collection list (which is an inherent problem criteria output requirement), the algorithm calculates spatial matching completely in-place using only three primitive integer cursors, maintaining a flat constant auxiliary footprint.

# Key Takeaways

✅ Core fundamental paradigm for processing multi-pointer search boundaries, array sorting reductions, and combinatorial unique sets filtering.

✅ **The Horizontal Skip Invariant:** When processing arrays with duplicate items, skip rules like `while (left < right && nums[left] == nums[left-1]) left++;` are highly strategic. They allow you to filter out duplicate triplet arrays directly *during* the generation phase inside the loop, completely bypassing the massive object allocation and hashing overhead of a `HashSet`.

✅ Directly drives real-world microarchitectures like **asymmetric portfolio arbitrage matchers** (filtering unique combinations of three separate asset indexes whose net balances cancel out transaction risk exposure to zero), graphical triangle wireframe rendering filters, and multi-variable signal balancing models.
