# 4Sum ([LeetCode 18](https://leetcode.com))

## Problem Statement

Given an array `nums` of `n` integers and an integer `target`, return *an array of all the **unique quadruplets** `[nums[a], nums[b], nums[c], nums[d]]` such that*:
- `0 <= a, b, c, d < n`
- `a`, `b`, `c`, and `d` are **distinct**.
- `nums[a] + nums[b] + nums[c] + nums[d] == target`

Notice that the solution set **must not contain duplicate quadruplets**. You can return the answer in **any order**.

# Intuition

This problem expands on the **3Sum** blueprint. A native brute-force approach using four nested loops would check all element combinations, triggering a highly sub-optimal $O(N^4)$ runtime penalty.

To optimize the search down to an efficient **cubic $O(N^3)$ time footprint with $O(1)$ auxiliary space**, we can chain **Sorting** with a **Nested Dual-Pivot Two-Pointer (Meet-in-the-Middle) Pattern**:
1. **Sort the array upfront.** This groups duplicate integers into contiguous blocks, making duplicate filtering trivial. It also establishes monotonic order so we can manipulate sums predictably.
2. **Fix Two Pivot Elements:** We run an outer loop with cursor `i` to fix the first element, and an inner loop with cursor `j` (starting from `i + 1`) to fix the second element. This reduces our 4Sum challenge down to a standard **Two Sum II (Sorted Array)** subproblem for the remaining elements, searching for a target pair sum equal to `target - nums[i] - nums[j]`.
3. **Bilateral Boundary Squeezing:** For the active pivot pair `(i, j)`, we anchor two pointers: `left = j + 1` and `right = N - 1`.
   - Calculate `sum = nums[i] + nums[j] + nums[left] + nums[right]`.
   - If `sum == target`, a valid quadruplet is found! We record it and slide both pointers inward (`left++`, `right--`).
   - If `sum < target`, our value is too small. We move `left++` to find a larger element.
   - If `sum > target`, our value is too large. We move `right--` to find a smaller element.
4. **Duplicate Pruning Guards:** To completely protect our results against duplicate entries without paying a performance penalty for a post-processing `HashSet`:
   - If `nums[i] == nums[i - 1]` (where `i > 0`), skip it.
   - If `nums[j] == nums[j - 1]` (where `j > i + 1`), skip it.
   - Once a valid quadruplet is located, skip duplicates for `left` and `right` continuously inside the inner loop.
5. **The Integer Overflow Trap:** When summing four integers, the intermediate calculation can easily breach 32-bit integer boundaries if `target` or elements are massive. To safeguard against overflow, we perform our mathematical checks using a 64-bit **`long`** primitive data type accumulator register.

# State Definition

The sorting-based dual-pivot multi-pointer reduction pipeline tracks spatial boundaries using four reference registers:

```java
int i = 0;              // Primary pivot tracking the first element of our quadruplet
int j = i + 1;          // Secondary pivot tracking the second element of our quadruplet
int left = j + 1;       // Squeezing pointer anchored at the lower bounds of the search space
int right = n - 1;      // Squeezing pointer anchored at the higher bounds of the search space
```

# Recurrence / Structural Squeezing Condition

```text
Sort(nums)
For i from 0 to n - 4:
    If i > 0 AND nums[i] == nums[i - 1] -> Continue (Skip duplicate first pivots)
    For j from i + 1 to n - 3:
        If j > i + 1 AND nums[j] == nums[j - 1] -> Continue (Skip duplicate second pivots)
        
        left = j + 1, right = n - 1
        While left < right:
            long sum = (long)nums[i] + nums[j] + nums[left] + nums[right]
            if sum == target:
                Record quadruplet
                left++, right--
                while left < right AND nums[left] == nums[left - 1] -> left++
                while left < right AND nums[right] == nums[right + 1] -> right--
            else if sum < target:
                left++
            else:
                right--
```

# Optimal Two-Pointer Sorting Reduction Solution

## Idea

We sort the array upfront to group duplicates and structure direction-based search constraints. By nesting a secondary pivot loop within the main loop and utilizing a meet-in-the-middle squeezing pass at the base level, we extract strictly unique quadruplets completely in-place.

---

## Java Code

```java
import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;

class Solution {
    public List<List<Integer>> fourSum(int[] nums, int target) {
        List<List<Integer>> result = new ArrayList<>();
        
        // Guard Condition: Arrays with less than four elements cannot form a quadruplet
        if (nums == null || nums.length < 4) {
            return result;
        }

        int n = nums.length;

        // Step 1: Sort the array upfront to group duplicates and structure monotonicity
        Arrays.sort(nums);

        // Step 2: Fix the primary pivot element 'i'
        for (int i = 0; i < n - 3; i++) {
            // Duplicate Guard A: Skip identical primary pivot elements
            if (i > 0 && nums[i] == nums[i - 1]) {
                continue;
            }

            // Early Exit Optimization: Check absolute structural boundary bounds
            // If the four smallest elements exceed target, no solution can exist on this loop track
            if ((long) nums[i] + nums[i + 1] + nums[i + 2] + nums[i + 3] > target) {
                break;
            }
            // If the current element plus the three largest elements falls short, this index track is dead
            if ((long) nums[i] + nums[n - 1] + nums[n - 2] + nums[n - 3] < target) {
                continue;
            }

            // Step 3: Fix the secondary pivot element 'j'
            for (int j = i + 1; j < n - 2; j++) {
                // Duplicate Guard B: Skip identical secondary pivot elements
                if (j > i + 1 && nums[j] == nums[j - 1]) {
                    continue;
                }

                // Sub-Layer Optimization: Check localized boundary bounds for the j-pivot
                if ((long) nums[i] + nums[j] + nums[j + 1] + nums[j + 2] > target) {
                    break;
                }
                if ((long) nums[i] + nums[j] + nums[n - 1] + nums[n - 2] < target) {
                    continue;
                }

                // Step 4: Initialize the Meet-in-the-Middle Two-Pointer pointers
                int left = j + 1;
                int right = n - 1;

                while (left < right) {
                    // Use a 64-bit long primitive accumulator to safely protect against integer overflows
                    long currentSum = (long) nums[i] + nums[j] + nums[left] + nums[right];

                    if (currentSum == target) {
                        // Valid quadruplet located -> compile structural match values
                        result.add(Arrays.asList(nums[i], nums[j], nums[left], nums[right]));

                        // Advance both pointers inward simultaneously
                        left++;
                        right--;

                        // Duplicate Guard C: Skip identical elements for the left pointer boundary
                        while (left < right && nums[left] == nums[left - 1]) {
                            left++;
                        }

                        // Duplicate Guard D: Skip identical elements for the right pointer boundary
                        while (left < right && nums[right] == nums[right + 1]) {
                            right--;
                        }
                    } else if (currentSum < target) {
                        // Sum is too small -> shift the left bound forward to find a larger value
                        left++;
                    } else {
                        // Sum is too large -> shift the right bound backward to find a smaller value
                        right--;
                    }
                }
            }
        }

        return result;
    }
}
```

## Complexity Analysis

Let N be the total length of the input array `nums`.

### Time Complexity

```text
Time Complexity: O(N³)
```
*Explanation:* Sorting the array takes $O(N \log N)$ time. The primary outer loop runs $N$ times. The nested secondary loop runs roughly $N$ times. The baseline meet-in-the-middle `while` loop scans the remaining elements via the left and right pointers linearly in $O(N)$ time. This nested $O(N \times N \times N)$ configuration bounds the total execution runtime complexity cubically to $O(N^3)$.

---

### Space Complexity

```text
Space Complexity: O(1) auxiliary space
```
*Explanation:* Highly optimal. Excluding the memory allocations required to store and return the final results collection list (which is an inherent output requirement), the algorithm operates completely in-place using only a fixed set of local primitive variables, preserving a flat constant auxiliary footprint.
