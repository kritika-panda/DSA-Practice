# Maximum Sum Combinations

## Problem Statement

Given two integer arrays `A` and `B` of size `N` each, and an integer `C`. You need to find the **C maximum sum combinations** consisting of one element from array `A` and one element from array `B`.

Return *the list of C maximum sum combinations sorted in **descending order***.

The overall runtime complexity must be strictly bounded by:

```text
O(N * log(N) + C * log(C))
```

*(where N is the size of the arrays A and B, and C is the number of max combinations requested)*

---

## Examples

### Example 1

**Input**

```java
A = [3, 2]
B = [1, 4]
C = 2
```

**Output**

```java
[7, 6]
```

**Explanation**

All possible combinations of sums are:
* `3 + 4 = 7`
* `2 + 4 = 6`
* `3 + 1 = 4`
* `2 + 1 = 3`
The 2 maximum sum combinations are `7` and `6`.

---

### Example 2

**Input**

```java
A = [1, 4, 2, 3]
B = [2, 5, 1, 6]
C = 4
```

**Output**

```java
[10, 9, 9, 8]
```

**Explanation**

The highest sums that can be formed are:
* `4 + 6 = 10`
* `4 + 5 = 9`
* `3 + 6 = 9`
* `3 + 5 = 8`

---

## Brute Force Approach

Compute all possible \(N^2\) sum combinations from arrays `A` and `B`, sort them all in descending order, and extract the first `C` elements.

### Steps

1. Create a large dynamic array or list to hold the combinations.
2. Run a nested loop with `i` from `0` to `N - 1` and `j` from `0` to `N - 1`.
3. Calculate `sum = A[i] + B[j]` and add it to the list.
4. Sort the entire combination list in descending order.
5. Slice and return the first `C` elements.

### Complexity

```text
Time Complexity: O(N^2 * log(N^2)) // due to generating and sorting all N^2 combinations
Space Complexity: O(N^2) to store all combinations in memory
```

Generating and sorting all combinations takes quadratic time and space. For arrays of size \(N = 10^5\), this will trigger a severe **Memory Limit Exceeded (MLE)** or **Time Limit Exceeded (TLE)** crash. We can optimize this by sorting both arrays first and utilizing a **Max-Heap**.

---

# Optimal Approach: Max-Heap with Index Coordinate Deduplication

## Key Idea

By **sorting both arrays `A` and `B` in descending order**, the absolute largest sum combination is guaranteed to be formed by the first elements of both arrays: `A[0] + B[0]`.

Instead of exploring all paths blindly, we can use a **Max-Heap** to evaluate potential paths greedily starting from `(0, 0)`:
1. **Sort Arrays:** Sort both `A` and `B` in descending order (or sort in ascending order and traverse backward from the end).
2. **Greedy State Node Initialization:** Create a Max-Heap that stores a custom node structure containing:
   - The current `sum = A[i] + B[j]`.
   - The index `i` from array `A`.
   - The index `j` from array `B`.
3. Push the absolute maximum pair `(0, 0)` onto the heap. Keep a `HashSet<String>` tracking `"i,j"` strings to **prevent processing duplicate index coordinate pairs**.
4. **Iterative Extraction:** Loop `C` times:
   - Extract the maximum node currently sitting at the root of the max-heap.
   - Append its `sum` directly to our results list.
   - **Lookahead Expansion:** The next largest sums must logically be formed by stepping one index forward in either array. Generate two candidate pairs:
     - **Path 1:** `(i + 1, j)`
     - **Path 2:** `(i, j + 1)`
   - For each path, if it falls within valid array boundaries and has not been added to our `visited` set yet, push it onto the max-heap.

This lets us extract exactly the `C` largest sums efficiently without exploring the remainder of the combination space.

---

## Visual Understanding

Suppose sorted arrays are `A = [4, 3]`, `B = [6, 5]`, and `C = 2`:

- **Initialization:** Push `(i:0, j:0) -> sum = 4 + 6 = 10` onto the heap. `visited = {"0,0"}`.
- **Iteration 1:**
  - Pop max node: `10` from `(0,0)`. Add `10` to result.
  - Expand candidates:
    - Path 1: `(1,0) -> sum = 3 + 6 = 9`. Unvisited! Push onto heap.
    - Path 2: `(0,1) -> sum = 4 + 5 = 9`. Unvisited! Push onto heap.
  - Heap state: `[9 (from 1,0), 9 (from 0,1)]`. `visited = {"0,0", "1,0", "0,1"}`.
- **Iteration 2:**
  - Pop max node: `9` from `(1,0)`. Add `9` to result.
  - Loop finishes since `C = 2` is satisfied.

The final output is `[10, 9]`, generated by touching minimal state transitions.

### Node Structural Definition

We wrap the state details cleanly into an optimized data placeholder class:

```java
class Node {
    int sum;
    int i;
    int j;
    Node(int sum, int i, int j) {
        this.sum = sum;
        this.i = i;
        this.j = j;
    }
}
```

## Correct Partition Condition

The index lookahead limits push elements into the queue only if they stay within structural array boundaries and have not been previously visited:

```java
if (i + 1 < N && visited.add((i + 1) + "," + j)) {
    maxHeap.offer(new Node(A[i + 1] + B[j], i + 1, j));
}
if (j + 1 < N && visited.add(i + "," + (j + 1))) {
    maxHeap.offer(new Node(A[i] + B[j + 1], i, j + 1));
}
```

## Java Solution

```java
import java.util.ArrayList;
import java.util.Arrays;
import java.util.HashSet;
import java.util.List;
import java.util.PriorityQueue;
import java.util.Set;

class Solution {
    // Custom tuple node to track values and grid coordinate configurations
    private static class Node {
        int sum;
        int i;
        int j;

        Node(int sum, int i, int j) {
            this.sum = sum;
            this.i = i;
            this.j = j;
        }
    }

    public List<Integer> solve(int[] A, int[] B, int C) {
        List<Integer> result = new ArrayList<>();
        if (A == null || B == null || C == 0) {
            return result;
        }

        int N = A.length;

        // Step 1: Sort both arrays in ascending order
        Arrays.sort(A);
        Arrays.sort(B);

        // Initialize a Max-Heap by reversing standard comparison order logic
        PriorityQueue<Node> maxHeap = new PriorityQueue<>((a, b) -> Integer.compare(b.sum, a.sum));
        // Set to store unique index string markers and prevent duplicate tracks
        Set<String> visited = new HashSet<>();

        // Step 2: Push the absolute maximum pair (A[N-1] + B[N-1]) onto the heap
        int i = N - 1;
        int j = N - 1;
        maxHeap.offer(new Node(A[i] + B[j], i, j));
        visited.add(i + "," + j);

        // Step 3: Loop exactly C times to extract the top sum combinations greedily
        while (result.size() < C && !maxHeap.isEmpty()) {
            Node curr = maxHeap.poll();
            result.add(curr.sum);

            i = curr.i;
            j = curr.j;

            // Lookahead Option 1: Step down array A (i - 1)
            if (i - 1 >= 0 && !visited.contains((i - 1) + "," + j)) {
                maxHeap.offer(new Node(A[i - 1] + B[j], i - 1, j));
                visited.add((i - 1) + "," + j);
            }

            // Lookahead Option 2: Step down array B (j - 1)
            if (j - 1 >= 0 && !visited.contains(i + "," + (j - 1))) {
                maxHeap.offer(new Node(A[i] + B[j - 1], i, j - 1));
                visited.add(i + "," + (j - 1));
            }
        }

        return result;
    }
}
```

## Complexity Analysis

### Complexity Metrics

| Operation | Time Complexity | Space Complexity | Reason |
| :--- | :--- | :--- | :--- |
| **Greedy Graph Search** | **O(N * log(N) + C * log(C))** | **O(C)** | Sorting both input arrays takes \(O(N \log N)\). The greedy extraction loop runs exactly `C` times. In each iteration, heap insertion and deduplication checks take \(O(\log C)\). The heap and visited sets store at most \(O(C)\) active elements. |

---

## Key Insight

Sorting the input arrays lets us organize combinations into a deterministic grid-like search space, enabling a max-heap to fetch the `C` absolute maximum combinations without paying the space or time cost of evaluating the remaining sub-optimal pairs.

```text
Time  : O(N * log(N) + C * log(C)) optimal log-linear scaling
Space : O(C) auxiliary tracking and output collection memory
```
